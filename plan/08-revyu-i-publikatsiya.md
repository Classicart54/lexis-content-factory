# Агент-ревьюер и публикационный контур

## Назначение

Ревьюер — последний автономный смысловой фильтр перед публикацией. Он не участвует в написании материала и не должен быть первым, кто ловит очевидный брак: перед ним уже обязаны пройти детерминированные проверки фактов, структуры, текста и визуальных слотов.

Ревьюер отвечает за то, что нельзя надежно поймать регулярками и схемой: пустые абзацы, слабый ответ на вопрос, рекламный тон, неочевидные неподтвержденные сравнения, некорректные выводы из фактов и визуальные слоты, которые выглядят красиво, но могут исказить смысл.

## Место в конвейере

1. Поисковик собирает факты.
2. Структурщик планирует материал.
3. Писатель пишет `draft.v1.json`.
4. Инфографик создает `infographics.v1.json`.
5. Сборщик кодом создает `assembled.v1.json`.
6. Машинный валидатор проверяет `assembled.v1.json`.
7. Ревьюер проверяет смысл и риски.
8. Паблишер отправляет материал на сайт или переводит в `published`.

Человека в обязательном процессе нет.

## Вход

Ревьюер получает:

- `PipelineRequest`;
- `FactPackage`;
- `MaterialStructure`;
- `assembled.v1.json`;
- `infographics.v1.json`;
- `ValidationReport` после машинной приемки;
- релевантный срез `ProjectKnowledge`.

Если `ValidationReport.ok === false`, ревьюер не должен героически чинить материал. Оркестратор обязан вернуть задачу владельцу ошибки до LLM-ревью.

## Выход

Ревьюер возвращает `ReviewReport`:

```json
{
  "requestId": "A-0001",
  "approved": false,
  "issues": [
    {
      "code": "generic_paragraph",
      "severity": "error",
      "owner": "writer",
      "message": "Блок implementation содержит абзац, который можно перенести в статью конкурента без изменений.",
      "path": "blocks[9].paragraphs[1]"
    }
  ],
  "summary": "Материал отвечает на тему, но требует доработки двух общих абзацев и одного visual_slot.",
  "checkedAt": "2026-08-09T..."
}
```

`owner` определяет маршрут возврата:

- `facts` — не хватает источника, дата/цитата/claim не подтверждают вывод;
- `structure` — материал не отвечает на вопрос, неверный порядок, не хватает раздела, CTA не вытекает из темы;
- `writer` — пустые абзацы, рекламный тон, слабые формулировки, неверная работа с FAQ/CTA;
- `system` — проблема формата, сборки, артефактов или публикационного адаптера.

## Что проверяет ревьюер

- Материал прямо отвечает на исходный вопрос темы.
- Лид не обещает больше, чем статья реально доказывает.
- Каждый раздел добавляет новую мысль, а не повторяет соседний блок.
- Нет пустых абзацев: если абзац можно вставить в статью конкурента без замены слов, он не нужен.
- Выводы следуют из `sourceClaimIds`, а не из общего знания модели.
- Текст не выглядит как рекламная страница Lexis Voice.
- CTA соответствует теме, а не является дефолтной кнопкой ко всем материалам.
- FAQ отвечает на реальные уточнения, а не добивает объем.
- Конкуренты не описаны через их маркетинговую рамку.
- Нет превосходных претензий: лучший, единственный, самый точный, гарантирует и похожее.
- Для legal/market/stat claims нет самоуверенных выводов без источника.
- `visual_slot` не добавляет новый смысл, которого нет в исходном блоке.
- `visual_slot` действительно помогает статье, а не дублирует таблицу декоративно.

## Что ревьюер не делает

- Не публикует материал.
- Не переписывает статью целиком.
- Не придумывает новые факты.
- Не добавляет новые ссылки и источники.
- Не заменяет машинный валидатор.
- Не требует участия человека.

## Критерии approve

Ревьюер ставит `approved: true`, если:

- машинная приемка уже прошла;
- нет блокирующих фактических рисков;
- материал отвечает на вопрос темы;
- нет явной воды и рекламной самоуверенности;
- визуальные слоты имеют смысл и не расширяют фактуру;
- CTA честно вытекает из темы и разрешенных продуктовых фактов.

## Критерии возврата на доработку

`needs_facts`:

- вывод не подтвержден claim/source;
- legal/stat/competitor утверждение звучит сильнее источника;
- не хватает даты снимка или цитаты;
- visual_slot требует данные, которых нет в исходном блоке.

`needs_structure_revision`:

- структура отвечает не на тот вопрос;
- важный раздел отсутствует;
- порядок ломает понимание;
- CTA выбран не под тему;
- visual_slot нужен раньше/позже по логике материала.

`needs_writer_revision`:

- абзацы пустые или слишком общие;
- блоки повторяют друг друга;
- тон рекламный;
- FAQ слабый;
- формулировки visual_slot brief слишком абстрактные.

`blocked`:

- материал нельзя честно выпустить без внешней фактуры;
- источники противоречат друг другу, а конвейер не может выбрать безопасную версию;
- публикационный формат сайта не поддерживает обязательный блок.

## Публикация

Паблишер запускается только после `approved`.

Реальный паблишер:

- взять `assembled.v1.json`;
- преобразовать его в формат сайта из `doc-schema.json`;
- отправить `{ "doc": ... }` в `CONTENT_API_URL`, обычно `http://127.0.0.1:3000/api/content`;
- передать `Authorization: Bearer <CONTENT_API_TOKEN>`;
- записать URL публикации и версию артефакта;
- не публиковать, если нет `reviewReport.approved === true`.

Коды ответа:

- `201` — материал опубликован;
- `200` — материал обновлен;
- `422` — сайт вернул список `problems[]`, конвейер превращает их в замечания и отправляет на доработку;
- `429` — лимит волны, материал не публикуется;
- `401`, `404`, `503` — проблема настройки публикационного контура.
