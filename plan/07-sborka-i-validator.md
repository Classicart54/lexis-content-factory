# Сборка JSON и машинная приемка

## Задача

Собрать итоговый материал в формате `{ meta, blocks }`, положить его в правильное место сайта и прогнать обязательные проверки до LLM-ревью.

## Сборка

Сборка не должна быть отдельным творческим агентом. Если структурщик и писатель работают в типизированной структуре, итоговый объект собирается кодом.

После агента-инфографика сборщик создает отдельный артефакт `assembled.v1.json`. Это уже не черновик писателя, а финальный документ для машинной приемки и ревью: текстовые блоки из `draft.v1.json` плюс вставленные визуальные плейсхолдеры из `infographics.v1.json`.

Сборщик не пишет новый текст и не придумывает визуалы. Он только:

- берет `custom_visual_slot` со статусом `derivable`;
- вставляет блок `visual_slot` после указанного `sourceBlockId`, после лида или перед CTA;
- переносит в блок `brief`, `dataContract`, `allowedData`, `forbiddenAdditions`, `visualGoal`, `tone`, `designFreedom`;
- сохраняет `sourceClaimIds`, чтобы ревьюер и публикационный слой видели происхождение данных;
- добавляет в `meta` служебные поля `assembledAt`, `kind`, `cluster`, `visualSlots`.

## Итоговый формат

```json
{
  "meta": {
    "kind": "compare",
    "slug": "...",
    "h1": "...",
    "seoTitle": "...",
    "description": "...",
    "updatedAt": "...",
    "cluster": "..."
  },
  "blocks": []
}
```

## Формат визуального слота в итоговом JSON

```json
{
  "id": "block-visual-slot-classification-levels",
  "type": "visual_slot",
  "title": "Карта уровней техник продаж",
  "sourceBlockId": "classification",
  "sourceClaimIds": ["F4", "F6"],
  "renderMode": "custom_visual_slot",
  "brief": "Собрать кастомную карту уровней техник продаж...",
  "visualGoal": "Помочь читателю быстро отличить уровни техник продаж.",
  "tone": "editorial",
  "designFreedom": "custom_composition",
  "dataContract": ["Использовать только строки исходной таблицы."],
  "allowedData": ["columns", "rows"],
  "forbiddenAdditions": ["новые факты", "новые числа"],
  "data": {}
}
```

## Машинные проверки

- JSON соответствует schema.
- `lead` ровно один, первый, 200-450 знаков.
- Заголовки блоков несут предмет; вопросная форма необязательна и используется только там, где звучит естественно.
- `seoTitle` и `description` входят в лимиты.
- Объем не меньше 1200 слов.
- Для `compare` есть `fork.neither` и `verdict`.
- FAQ содержит минимум 8 вопросов.
- Нет запрещенных претензий и превосходных степеней про продукт или рынок.
- Лид не использует конструкцию `не X, а Y`; в теле такая конструкция встречается не больше двух раз.
- Все источники имеют дату снимка.
- Кластер не занят.
- Вердикт не похож на уже опубликованные.
- Ссылки внутренние, `related` без дублей и без self-link.

## Цикл доработок

- Ошибка структуры возвращается структурщику.
- Ошибка объема, FAQ, формулировок и акцентов возвращается писателю.
- Ошибка факта или источника возвращается в контур фактуры.
- Ошибка кластера возвращается на этап брифа.

## Результат этапа

Материал, прошедший машинную приемку, или детальный отчет об ошибках с адресной маршрутизацией на доработку.
