# Хранение артефактов

## Задача

Артефакты должны храниться так, чтобы материал можно было восстановить, проверить, пересобрать и объяснить через несколько месяцев.

## Директория данных

Для локальной версии:

```text
data/
  requests.json
  requests/
    A-0001/
      request.json
      facts.v1.json
      structure.v1.json
      draft.v1.json
      infographics.v1.json
      assembled.v1.json
      validation-report.v1.json
      review-report.v1.json
      revision.v1.json
      provenance.json
```

## Версионирование

Каждая доработка создает новую версию артефакта:

```text
brief.v1.json
brief.v2.json
facts.v1.json
facts.v2.json
draft.v1.json
draft.v2.json
```

Первая файловая реализация пока перезаписывает текущие `*.v1.json` артефакты. Это сознательное упрощение для ранней версии. Логика `revision.v1.json` уже отделена, поэтому позже можно заменить запись на настоящие версии `v2`, `v3` без изменения контрактов агентов.

В `request.json` хранится указатель на текущие версии:

```json
{
  "currentVersions": {
    "brief": 2,
    "facts": 1,
    "structure": 3,
    "draft": 4,
    "validationReport": 4
  }
}
```

## Почему не перезаписывать файлы

- Можно понять, что именно изменилось после замечания.
- Можно откатиться к предыдущему артефакту без потери истории.
- Можно сравнивать качество разных моделей и промптов.
- Можно объяснить опубликованный материал через provenance.

## Индекс заявок

`data/requests.json` нужен только для быстрого списка заявок:

```json
{
  "nextNumber": 2,
  "requests": [
    {
      "id": "A-0001",
      "status": "brief_draft",
      "title": "Ассессмент-центр или тест-звонок",
      "updatedAt": "2026-08-08T10:00:00.000Z"
    }
  ]
}
```

Полные данные лежат в директории конкретной заявки.

## Формат ошибок

Ошибки и предупреждения хранятся в отчетах, а не только в логах процесса. Лог может потеряться, отчет является частью истории материала.

## Формат ревизии

Когда машинная приемка или LLM-ревьюер возвращают блокирующие ошибки, оркестратор сохраняет `revision.v1.json`:

```json
{
  "requestId": "A-0001",
  "source": "llm_review",
  "targetStatus": "needs_writer_revision",
  "targetOwner": "writer",
  "attempt": 1,
  "issues": [],
  "instructions": ["Rewrite only the affected block..."],
  "createdAt": "2026-08-09T..."
}
```

Этот файл нужен, чтобы следующий агент понимал, какие именно замечания исправлять. Те же инструкции добавляются в `request.notes`, потому что агенты уже получают `PipelineRequest` в своем входе.

## Что коммитить

В репозиторий кода не коммитятся:

- `.env`.
- `data/`.
- токены.
- временные ответы моделей.

В будущем можно завести отдельный приватный репозиторий или S3-хранилище для артефактов производства.
