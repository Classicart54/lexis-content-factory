# Контракты ИИ-агентов

## Общий принцип

Агент — это не чат с ролью, а функция с четким входом, выходом, ограничениями и критериями приемки. Все агенты должны возвращать структурированные данные, а не свободный текст.

## Поисковик

### Назначение

Найти новостные поводы и собрать публичную фактуру там, где она допустима.

### Вход

- `Brief`.
- Список известных источников из репозитория сайта.
- Список конкурентов, если применимо.

### Выход

- `FactPackage`.

### Обязательные правила

- Каждый факт имеет источник и дату снимка.
- Факты о конкурентах помечаются `requiresStrictSource: true`.
- Если факт не найден, он попадает в `missingFacts`.
- Поисковик не пишет статью и не делает финальный вывод.

## Оркестратор

### Назначение

Выбрать следующий шаг и маршрутизировать ошибки.

### Вход

- `Request`.
- Текущие артефакты.
- Последний отчет проверки или ревью.

### Выход

```json
{
  "nextStatus": "needs_facts",
  "assignee": "search_agent",
  "reason": "Не хватает источника по тарифам конкурента",
  "requiredArtifacts": ["facts.json"]
}
```

### Обязательные правила

- Оркестратор не пишет материал.
- Оркестратор не исправляет факты из головы.
- Оркестратор не отключает проверки.
- Ошибки маршрутизируются по `owner` из отчета проверки.

## Структурщик

### Назначение

Собрать индивидуальную структуру материала под тему.

### Вход

- `Brief`.
- `FactPackage`.
- Список разрешенных типов блоков.
- Лимиты формата.

### Выход

- `MaterialStructure`.

### Обязательные правила

- `lead` всегда первый и один.
- Для `compare` обязательны `table`, `fork`, `verdict`, `faq`, `cta`.
- Для `compare` в `fork` должен быть `neither`.
- Заголовки смысловых блоков формулируются как вопросы.
- Каждый блок имеет `purpose` и список `requiredFactIds`.
- Если фактов не хватает для честного блока, структурщик возвращает `missingFacts`.

## Писатель

### Назначение

Заполнить структуру материалом в формате сайта.

### Вход

- `Brief`.
- `FactPackage`.
- `MaterialStructure`.

### Выход

- `DraftDoc`.

### Обязательные правила

- Писатель использует только факты из `FactPackage`.
- Определения терминов не переформулируются.
- Внешние ссылки на конкурентов не вставляются в текст.
- В каждом разделе есть конкретика: факт, число, механика, ограничение или проверяемый источник.
- Вердикт отвечает на вопрос выбора, а не пересказывает статью.
- FAQ содержит реальные вопросы.

## Инфографик

### Назначение

Определить, какие визуальные блоки можно вывести из данных материала.

### Вход

- `MaterialStructure`.
- `DraftDoc`.

### Выход

```json
{
  "requestId": "A-0001",
  "visuals": [
    {
      "kind": "hero_compare",
      "sourceBlockPath": "doc.blocks[4]",
      "status": "derivable"
    }
  ],
  "missingData": []
}
```

### Обязательные правила

- Инфографика выводится из данных, а не генерируется свободно.
- Если данных нет, визуал не создается.
- Новый тип визуализации сначала описывается как структура данных.

## Ревьюер

### Назначение

Проверить смысл после машинной приемки.

### Вход

- `Brief`.
- `FactPackage`.
- `DraftDoc`.
- `ValidationReport`.

### Выход

- `ReviewReport`.

### Обязательные правила

- Ревьюер не заменяет машинную приемку.
- Ревьюер проверяет глубину, честность, границы применимости и отсутствие пустых абзацев.
- Ревьюер не переписывает весь материал сам.
- Замечания должны указывать блок, проблему и владельца исправления.
