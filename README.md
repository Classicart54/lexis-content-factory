# Lexis Content Factory

Актуальное сопровождение и проверка работы: [docs/server-deploy.md](docs/server-deploy.md).
Инструкции coding-агенту: [AGENTS.md](AGENTS.md).

Telegram-бот для запуска конвейера материалов Lexis Voice без отдельного веб-интерфейса.

## Что уже умеет

- Заводить заявку на тему из плана.
- Заводить заявку на новость.
- Пошагово собирать бриф.
- Показывать список заявок.
- Показывать карточку заявки по id.
- Выполнять следующий шаг конвейера через `/run <id>`.
- Прогонять конвейер до конечного статуса через `/run_all <id>`.
- Возвращать замечания ревьюера нужному агенту через `revision.v1.json`.
- Собирать итоговый `assembled.v1.json` с `visual_slot` под кастомную инфографику.
- Показывать отчет за день через `/report`.
- Хранить заявки и артефакты локально в `data/requests.json` и `data/requests/<id>/`.

## Запуск

1. Создать `.env` по примеру `.env.example`.
2. Заполнить `TELEGRAM_BOT_TOKEN`.
3. При необходимости ограничить доступ через `ALLOWED_TELEGRAM_USER_IDS`.
4. Чтобы включить реального агента-поисковика, заполнить `NEUROMEDIA_API_KEY`.
5. Запустить:

```bash
corepack pnpm install --frozen-lockfile
corepack pnpm dev
```

Для production-сборки:

```bash
corepack pnpm build
corepack pnpm start
```

## Безопасность токена

Токен Telegram-бота нельзя коммитить в репозиторий. Он должен храниться только в `.env` или переменных окружения. Если токен был отправлен в чат или попал в публичное место, его лучше перевыпустить в BotFather.

## Команды бота

- `/new` — создать новую заявку.
- `/list` — показать активные заявки.
- `/show A-0001` — показать карточку заявки.
- `/run A-0001` — выполнить один следующий шаг конвейера.
- `/run_all A-0001` — прогнать заявку до `monitoring`, `blocked` или другого состояния без следующего действия.
- `/topics` — показать очередь тем из `handoff-konveyer/fakty/temy.json`.
- `/take_topic tehniki-prodazh` — создать заявку из готовой темы очереди.
- `/report` или `/today` — отчет за сегодня: сколько создано, сколько дошло до monitoring, сколько в работе и что заблокировано.
- `/cancel` — отменить текущий диалог сбора брифа.

Если `NEUROMEDIA_API_KEY` не задан, конвейер использует мок-агентов. Если ключ задан, реальные агенты работают через Neuromedia API, модель `gpt-5.6-terra`: поисковик, структурщик, писатель, инфографик и ревьюер.

Если `HANDOFF_KONVEYER_DIR` задан, агенты получают машинно выгруженную фактуру из `fakty/`: очередь тем, продуктовые факты, кейсы, конкурентов, термины, глоссарий и внутренние ссылки. Это источник правды для Lexis Voice; продуктовые факты нельзя брать из открытого поиска.

## Контент-план

Контент-план лежит не в этом репозитории, а в handoff-папке сайта:

```text
handoff-konveyer/fakty/temy.json
```

В текущей выгрузке там 104 темы. Для каждой темы есть slug, URL, тип материала, вопрос, кластер, спрос и волна. Бот читает этот файл через `HANDOFF_KONVEYER_DIR` и показывает очередь командой `/topics`.

Связанные файлы фактуры лежат рядом:

- `produkt.json` — продуктовые факты Lexis Voice.
- `keysy.json` — кейсы и метрики внедрений.
- `konkurenty.json` — профили конкурентов.
- `terminy.json`, `glossariy.json` — определения и глоссарий.
- `vnutrennie-ssylki.json` — разрешенные внутренние ссылки.

## Где смотреть результаты

Для каждой заявки создается папка:

```text
data/requests/A-0001/
```

Главные файлы:

- `request.json` — статус, бриф, заметки оркестратора.
- `facts.v1.json` — факты и источники.
- `structure.v1.json` — структура материала.
- `draft.v1.json` — текст от писателя.
- `infographics.v1.json` — спецификации визуалов и `visual_slot`.
- `assembled.v1.json` — итоговый материал для публикации.
- `validation-report.v1.json` — машинная проверка.
- `review-report.v1.json` — LLM-ревью.
- `revision.v1.json` — последние замечания, отправленные агенту на доработку.
